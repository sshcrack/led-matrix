# Implicit state-machine inventory

Audited 2026-11-06 at `9312e85a`; re-audited 2026-11-08 at `96cc76d2` after the web UI overhaul, Desktop Handoff/Preset Persistence/Plugin Activation deepening and browser-based Spotify setup. Rows touched on 2026-11-08 link to current files; the others keep the line numbers of `9312e85a`.

This inventory identifies **73 machines or recurring machine families** across the Pi daemon, desktop app, web UI, shared libraries, plugins, scene worker, preview tooling and update script. A family groups repeated small implementations; this is not a count of individual object instances or every particle. States below are inferred descriptions unless the text identifies an existing enum/union.

A state machine here means retained history that changes which action is legal or what happens next, including history encoded by pointer/future presence, flags, sentinel values, counters, timestamps, process handles and call order. Ordinary settings, instantaneous predicates, continuous visual equations and external-library internals are excluded. Existing explicit state labels are included when substantial surrounding behavior remains implicit. Source links point to the audited revision's line numbers.

## Original priorities (implemented below)

1. **Render placement/session/worker recovery**: a distributed protocol with warmup, held frames, freshness, identity and crash-loop suppression. Preserve the distinction between a connected worker, a compatible worker, a requested session and a usable frame.
2. **SpotifyMV replacement**: current and pending playback coexist. Model request generation, search/decoder completion, promotion and cancellation together; a single Playing/Downloading flag cannot express this.
3. **Scene Lab**: browser revision, server generation, session identity and expiring lease are different concepts. An active session can be blocked on inputs or effectively expired.
4. **Automatic Director**: separate track introduction, event consumption, dwell/phrase waiting and failure cooldown; these are concurrent pieces of history, not mutually exclusive modes.
5. **Desktop updater and web saves**: boolean combinations carry workflow phases and in-flight identity. Make completion apply to the specific operation/draft that was submitted.
6. **Live preview**: retain independent socket, visibility and outstanding-demand state. A connection must never become demand by itself.

## Small supporting lifecycles and scope limits

- Preview generation adds a **fixture run** lifecycle: resolve/validate providers → `begin` → per-frame `update` → `end`/cleanup, with disabled/missing/failed scene outcomes. See [preview generator](../src_preview_gen/main.cpp), [provider contract](../shared/matrix/include/shared/matrix/preview.h), [audio provider](../plugins/AudioVisualizer/matrix/AudioPreviewProvider.cpp), [Spotify provider](../plugins/SpotifyScenes/matrix/SpotifyPreviewProvider.cpp) and [shader preview provider](../plugins/Shadertoy/matrix/preview/ShaderPreviewProvider.cpp). Execution-mode enums are environment selection, not themselves hidden workflow phases.
- Common resource lifecycles recur in UDP servers, downloader cancellation, GL context setup, shader-file watching, cached font loading, config migration/load/save, plugin discovery and subprocess helpers. They encode uninitialized/started/stopping/released or absent/loading/ready/failed through handles and call order. These are supporting instances of the runtime/resource and async-work families above, rather than additional app-wide modes.
- Tiny UI families are intentionally grouped. Other instances include scene-gallery selection/filter state, provider choice, preset rename/delete confirmation, schedule drafts, shader cache editing/deletion, theme selection and generated-preview failure fallback. Radix/ImGui/library-owned widget machines are outside this inventory.
- Pure analytic shaders and continuous simulation variables are not each counted as finite control machines. A drop crossing a lifetime threshold is included as a lifecycle; a sine wave's angle is not. Grid algorithms can of course be described mathematically as state-transition systems, but that broader definition would make nearly every animation a state machine.
- This is a static source audit using broad flag/enum/future/ref/timer searches followed by transition tracing. It is a comprehensive application-level inventory, not a formal proof that no additional implicit machine exists. No build or runtime test was needed for this documentation-only change.

## Important invariants to preserve in any later refactor

- Producer ownership must be established before enabled status can allow a standby desktop to send bulk UDP.
- Remote frames belong to a session, dimensions and increasing sequence; a matching scene name alone is insufficient identity.
- Existing local rendering continues while remote rendering warms, and short stalls hold the remote image before falling back.
- Track replacement completion must match the latest request generation before promoting a pending engine; artwork adoption must match the requested track identity.
- Scene Lab mutation must match both owning session and expected generation; effective expiry is distinct from stored `active`.
- Live capture is performed only for outstanding demand. Hidden/offscreen clients stop issuing requests, and duplicate requests coalesce.
- Teardown must destroy plugin-provided objects and callbacks before unloading their shared libraries.
- An HTTP update request succeeding, an update being queued for shutdown, and the new version passing health checks are separate milestones. Only the SUCCESS status (from the `.update_success` marker) means the update is installed.
- A Spotify sign-in callback must match the current attempt's state and arrive before it expires; every exit after `take()` records `succeed()` or `fail()`, because the browser that started the attempt waits on that phase.
